# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

LangReader is a phone-first web app (PWA) for reading Italian. It copies the look and gestures of Apple Books (paginated pages, themes, page curl) and the learning features of LingQ (blue/yellow word statuses, LingQs, phrases, "page turn marks blue words known"). It's plain HTML/CSS/ES modules: **no build step, no package.json, no CDN**. The only third-party code is the vendored Piper voice runtime in `vendor/`. All user data stays on the device.

## Running and deploying

- Run locally: `python3 -m http.server 8000`, then open http://localhost:8000. ES modules and the service worker need http(s), not `file://`.
- Deploy: GitHub Pages serves `main` from the repo root (https://stephenedgerton.github.io/LangReader/). Merging to `main` is the deploy. So far the workflow has been: work on branch `langreader-app`, open a PR, merge.
- **On every release, bump `VERSION` in `sw.js`, and add any new file to its `SHELL` list**, or installed home-screen copies keep stale or missing modules. The service worker is network-first for same-origin requests and falls back to its cache offline.

## Tests

- Run everything: `node --test` (Node 22+, takes about 20 s). One file: `node --test tests/words.test.mjs`. One test by name: `node --test --test-name-pattern="hold and drag"`.
- `tests/text.test.mjs` holds plain unit tests for `js/text.js`. The other files drive the real app in headless Chromium through Playwright, at the iPhone 13 viewport (390×664).
- `tests/helpers.mjs` starts a static server for the repo on a random port. `openApp()` opens a fresh browser context, mocks `en.wiktionary.org` (the `WIKTIONARY` fixture map; any other title returns 404) and `api.mymemory.translated.net`, marks the tips as seen, and collects page errors. Tests assert that the error list is empty. Pass `settings` to preset `langreader.settings`, `tipsSeen: false` to show the tips card, or `mt: null` to make translation fail.
- Playwright is loaded with `createRequire`, so a globally installed copy (`NODE_PATH`) works. There's no `package.json`. Elsewhere, install Playwright and its Chromium first.
- Most tests use the bundled *Un caffè a Bologna*, its opening sentence and the words in it (`treno`, `arrivò`, `valigia` …). Changing that story's text will break tests.
- There's no linter.
- `tests/training.test.mjs` drives the Training tab (Focus mode too: tests that record speech prefix English utterances with `en:`) and `tests/mysentences.test.mjs` your own sentences and packs; tests that click through Listen stub `speechSynthesis.speak` to record what's said. Deleting asks with `confirm()`, so those tests accept dialogs (`page.on('dialog', …)`).

## Architecture

`index.html` holds the static shell: five tab views (Home, Library, Training, Vocabulary, Stats), the `#reader` overlay, and one shared bottom `#sheet`. `js/app.js` boots the app (loads vocabulary, adds bundled stories, registers the service worker) and renders the Home, Library and Vocabulary tabs as HTML strings (the Stats tab is `statsview.js`, Training is `trainview.js`). `js/reader.js` owns everything inside the reader.

### Data (`db.js`, `vocab.js`, `settings.js`)
- IndexedDB `langreader` has these stores: `books` (metadata and progress; `chapterTitles` and `chapterWords` are denormalised here), `chapters` (key `${bookId}:${idx}`, `blocks: [{t:'h'|'p', x}]`), `words` (vocabulary), `tcache` (translation and dictionary cache), `days` (daily stats) `collections` (`{id, name, created}`; a book lists the ones it's in as `book.collections: [id]`) `sentences` and `packs` (Training's, see below). Adding a store means bumping `DB_VERSION` and adding it in `onupgradeneeded`.
- In the UI a saved word or phrase (status 1–4) is a **gem** ("+ Gem", "Gems (learning)"); never show the word "LingQ" to users. The code, comments and data keys still say LingQ/`lingqs`.
- Word status: a missing entry (status 0) is New/blue, 1–4 are LingQ levels (yellow), 5 is Known and -1 is Ignored. `setWord` *deletes* an entry that ends up at status 0 with no meaning. Terms are normalised by `normalize()` in `text.js`: lowercase NFC, with `’` turned into `'`. A phrase is stored as its normalised tokens joined by single spaces, with `phrase: true`.
- `vocab.js` keeps every word in an in-memory `Map` loaded at boot, and notifies `onChange` listeners. The reader recolours matching `.w[data-w]` spans in place, and re-renders the whole chapter when a phrase changes, because phrase underlines are computed at render time.
- A word entry keeps `example` (the sentence it was saved from, set once) and `exampleTr` (that sentence's translation, once the user translates it). Phrase entries also keep `display`, the text as printed with its punctuation.
- `names.js` lists names that `ignoreNames()` in `app.js` marks Ignored on first launch through `setMany` (which never touches existing entries). Bump `NAMES_VERSION` after adding names. Leave out names that are also ordinary words. These pre-seeded names don't count toward the backup reminder.
- Settings live in localStorage `langreader.settings`, behind a Proxy that saves on every write (avoid writing in hot paths). The Library's filter chip and sort order are `settings.libraryFilter` (`all`/`reading`/`unread`/`finished`/`c:<collection id>`) and `settings.librarySort`. Other localStorage keys: `langreader.seeded`, `langreader.samplesAdded`, `langreader.tipsSeen`, `langreader.lastBackup`, `langreader.backupSnooze`, `langreader.namesIgnored`, `langreader.badges`, `langreader.srsDay`, `langreader.trainDay`, `langreader.packRevs`, `langreader.trainIntros`. Training's focus pack and the pack New Sentence last used are `settings.trainFocus` and `settings.trainLastPack`; Focus mode's are `settings.focusMode` and `settings.focus`.

### Text and rendering (`text.js`)
- `tokenize` splits elisions the way LingQ does (*dell'anno* → *dell'* + *anno*) and keeps the apostrophe only on known truncations (*po'*). `paragraphHTML` wraps sentences in `.sent` and words in `.w` spans carrying status classes `s0`–`s4`, plus `ph` for words inside a saved phrase. Phrases match within one paragraph only, so a selection can't cross paragraphs. How the classes look depends on `#reader[data-hl]`: `underline` (LingQ's style, the default) or `background`.
- `textToChapters` splits pasted or .txt text on headings like "Capitolo N". `importer.js` also splits chapters longer than about 4000 words, and has its own minimal ZIP reader (built on `DecompressionStream`) for EPUB.

### Reader (`reader.js`)
- Pages come from **CSS multi-column layout**: `#page-content` is one column-filled element shifted by `translateX(-page * R.step)`. The page count comes from the position of the trailing `.end` marker. Which page each word span is on (`R.pageOf`) is computed lazily from bounding rects and reset by `layout()`. Only one chapter is in the DOM at a time.
- One pointer pipeline in `initGestures()` decides between a tap (open the bubble, turn at the edges, toggle the controls), a long press (≈480 ms; then dragging extends a phrase selection, up to `MAX_PHRASE` words), and a horizontal drag (page curl or slide). A flick needs at least 30 px, and a tap within 450 ms of the bubble or a sheet closing does nothing, so taps on them can't fall through and turn the page. `#page-area` has `touch-action: none` so iOS can't cancel these gestures. `R.busy` blocks input while a turn animates.
- Page curl (`curl.js`): `beginCurl` builds two full-screen copies of the turning page (`curlPage()`: **a clone of `#page-content`** plus the running head and page number) and the real element moves to show the page underneath. One copy is the front; the other is mirrored across the fold at low opacity as the see-through back of the flap. The curl layer sits above the page number but below the buttons. The clone keeps the duplicate id on purpose, because the reading styles are keyed on `#page-content`. The curl is skipped on wide two-column layouts (≥900px) and at chapter boundaries, which use a slide or fade instead.
- Mark Chapter Complete marks the chapter's blue words Known and records them in `book.progress.marked[chapter]`, so its Undo toast, or Mark Chapter Not Complete in the menu later, can revert exactly those. For chapters completed before that was recorded, `guessMarked()` takes the biggest same-timestamp batch of the chapter's plain Known words.
- A swipe up on the page (or ↑, or the menu's Mark Page as Known) calls `markPageKnown()`: `leavePage(page, true)` marks the page's blue words Known without turning, even with `autoKnown` off; the page is still counted as read only once.
- `leavePage()` runs on every forward turn: it bumps the stats and marks the page's blue words Known, with Undo through `revertToNew`. Words inside `h1`/`h2` are excluded.

### Library organising (`collections.js`)
- `filterBooks()` and `sortBooks()` (async, because "Easiest first" awaits `difficulty()`) feed `renderLibrary()` in `app.js`, which also has a title/author search. `organiseSheet()` (the Library's sort button) picks the order and renames or deletes collections; `bookCollectionsSheet()` (book ⋯ → Collections…) ticks a book in or out of collections. Collections are in the JSON backup. The series ships with its own collection (id `casa-gialla`, `created: 0` so it's first, with `series` set): `addBundledStories()` makes it once (tracked in `langreader.samplesAdded` as `collection:casa-gialla`, so a deleted one stays deleted) and adds newly shipped series books to it while it exists. A collection with `series` is always listed by `seriesOrder()`, book 1 first, whatever the sort.

### Reading goals (`goals.js`)
- Each book can have `goal: {pages, since, cheered}` (pages a day). Progress is the reading *position* in words (`wordsAt`), so jumping ahead counts and re-reading doesn't count twice. `progress.frac` says which page to reopen at; `progress.read` (page / pages, or 1 once the book is finished) is how much of the chapter is behind you, and is what goals and `bookPct` use.
- `trackProgress()` runs on every `saveProgress()` in the reader: it keeps `book.log[date] = {from, to}` (today's pages = to − from) and `book.milestones` (25/50/75/100% → date reached; `null` for ones passed before tracking started, which aren't celebrated). It returns celebrations, which the reader shows one at a time in `#r-cheer` at the top, clear of the bottom toasts.
- `trackProgress()` also keeps `book.reads`, one entry per read-through, for a future "read this year" round-up: `{started, finished}` as date keys. A read starts on the first save with the position past 0 (opening a book doesn't count) and finishes when milestone 1 is reached, taking its date (`null` = before tracking). No `finished` key means it's still in progress. "Start from the beginning" clears the milestones, so the next page read starts a new read and the old one stays. Books from before reads existed get one from `pastReads()` (first log day with progress, `null` if the log began mid-book). `finishedOn()` gives the latest finish; badges use it, so a restarted book stays finished. The Library ⋯ menu's "Mark as complete" (`markBookComplete()`) moves the position to the end and runs `trackProgress()`, finishing the read (started today if there wasn't one); it doesn't mark words Known.
- A "page" is `settings.wordsPerPage`, measured by `layout()` from the current chapter (only when it has 3+ pages), so it follows text size.
- The goal sheet opens from the reader menu, the Library ⋯ menu and Home's goal cards.

### Difficulty and achievements (`difficulty.js`, `achievements.js`)
- A book's difficulty is the share of its distinct words that are New (status 0), leaving out Ignored ones, as LingQ rates lessons. Each book's word list is built from its chapters once per session and kept in memory. `fillDifficulty()` fills `[data-diff]` placeholders after a view renders (`data-long` gives the full wording).
- Badges (known words, words read, best streak of days meeting the minutes goal, books finished, cards reviewed, best streak of days with a review) are all derived from data. Review counts are `days[].reviews`, bumped once per rated card in the review sheet (not for "Go over the ones I missed"), and taken back by Undo. Only the date each was earned is stored, in `langreader.badges`. `boot()` runs the first check so badges you already had are recorded quietly (date `null`). After that, the reader checks 2 s after each progress save and celebrates new ones in `#r-cheer`, and the review's end screen shows new ones in `.rv-badges`.

### Word frequency and the Stats tab (`freq.js`, `themes.js`, `statsview.js`)
- `data/freq-it-v1.json` ranks the 20,000 most common lemmas in 199 Gutenberg novels: `lemmas: [[lemma, count, "form|form…"]]` plus `total` (all non-name tokens). It's built offline by `tools/build-freq.mjs <morph-it.txt> <corpus dir>` (Morph-it! for form → lemma; `EXTRA` there holds hand-checked forms, and `DUMP_AMBIGUOUS=<n>` prints how frequent ambiguous forms were read). `sw.js` serves `data/` cache-first from the assets cache, so a rebuilt list needs a new file name (`-v2`) and a matching `URL` in `freq.js`.
- `freq.js` loads it once (boot starts the fetch) into a `Map` form → index. Listed forms win over a lemma spelled the same (*era* is *essere*). A lemma is known when any of its forms is Known; Ignored counts as known for coverage and bands but not for the known count or the level. Phrases don't count. `wordStats()` gives the level, coverage and bands; `themeWords()` a theme's words with their state.
- `recordSnapshot()` writes `lemmas`, `cover` and `coverL` into today's `days` record through `record()` in `stats.js` (fields that are set, not added). It runs at boot, when the reader closes and when the Stats tab renders; the trend reads these.
- The Stats tab's Training section (`trainingHTML()` in `statsview.js`) counts the sentences in the packs you train: "can say" is `learned()` (say card stable for a week), plus mastered and started; the training streak, training days in the last 30, cards this week, a 14-day bar chart of `days[].drills` with a hover tooltip (and a screen-reader table), and each trained pack's learned/started bar. Before any training it shows a one-line placeholder.
- The bubble's `.wp-freq` tag and the card's `.freq-line` come from `freqTagHTML()` / `freqSentence()`. The reader passes `isCommon` to `paragraphHTML`, which adds `c` to spans of the 2,000 most common lemmas; `#reader.common-hl` (`settings.commonHL`) styles `.s0.c` stronger and other `.s0` lighter. The in-place recolouring keeps `c`.
- Theme lists in `themes.js` are lemmas; any word that isn't a lemma in the list is dropped silently, so check new ones against the data file.

### Reviews (`srs.js`, `review.js`)
- LingQs (status 1–4) are spaced-repetition cards scheduled by FSRS-5 with default weights. `srs.js` is pure (unit-tested in `tests/srs.test.mjs`); the card lives on the word entry as `srs: {s, d, last, due, reps, lapses, tap}`. A LingQ without `srs` is a new card.
- Reading is review: `leavePage()` passes the page's LingQs (words, plus phrases via `.ph0`) and `R.tapped` (terms tapped in this chapter) to `creditReading()`. Each card gets one credit a day: read past → Good, tapped → Again (once a day, `srs.tap`). A LingQ saved today is left alone. Writes go through `updateMany()` in `vocab.js`.
- Levels follow stability up (`levelFor`) but never down, except Again drops one level. A card with stability ≥ 180 days becomes Known and leaves the reviews.
- The day is capped (`settings.reviewsPerDay`, `settings.newPerDay`); `buildQueue()` orders due cards by (1 − recall) × word weight (frequency dots; phrases 3) and new cards by weight. Counts done today are in localStorage `langreader.srsDay`. The UI only shows today's share, never the backlog; "Review 10 more" raises today's cap for the session. `settings.retention` (relaxed/normal/intense = 80/85/90%) sets intervals.
- The review sheet (`reviewSheet()`) opens full screen (`openSheet(…, {full: true})`: no scrim tap or swipe-down to close, only its own buttons). Its card is a 3D flip card (`.card3d` with `.face.front`/`.face.back` stacked in one grid cell). Flashcards can be swiped (right → Good, left → Again); the rated card is cloned into `#sheet` as `.rv-fly` to fly off while the next one renders. With `settings.reviewStyle` `'mixed'` (the default), due cards take turns by `srs.reps % 3`: flashcard, fill the gap (`cloze`, needs the word in its `example`) and pick the meaning (`choice`); distractors come from your other words. New and forgotten cards are always flashcards. A right pick rates Good, a wrong one Again. Tests that click through flashcards preset `reviewStyle: 'flip'`.
- On the back of the card you can play the word and its sentence, fix the meaning (inline edit, or tap a suggestion in the Dictionary panel, built from `dictHTML()`/`dictionaryHints()` in `wordcard.js`). Undo (button or Z) restores the card's previous `status`/`srs` and today's counts. Keys: Space flips, 1–4 rate or pick, ←/→ swipe.
- The card's sentence is built by `sentenceHTML()`: every other word is a `.cw` span coloured by status; tapping one opens the reader's word bubble (`openCardBubble()` in `bubble.js`), as it does on Training cards. The back offers "Translate sentence", which saves `exampleTr`.
- When today's cards are done, the end screen offers optional extras under Done (and Home's finished card stays tappable): "Review N more" while due or new cards remain, otherwise "Practise N ahead of schedule" (items with `ahead`: rated for real, not counted in `langreader.srsDay`), plus "Go over the ones I missed" (items with `practice`: no rating, the schedule is untouched).

### Training (`sentences.js`, `training.js`, `trainview.js`, `mysentences.js`, `drill.js`, `focus.js`, `samples/packs/`)
- The Training tab drills sentences for listening and speaking; `docs/training-plan.md` has the decisions and the plan for what comes next. Word reviews live here too: the review sheet opens from the tab's "Bonus: N words" row (or as a step, with `settings.trainWords`). Home has one "Today's Training" card (`trainingCardHTML()`) that opens the tab; there's no review button on Home or Vocabulary any more.
- A sentence (IndexedDB `sentences`) is `{id, it, en, ctx, packs: [id], order, created, cards: {listen, say}, bundled?, from?, paused?, hidden?, edited?}`. `packs` works like `book.collections`: a sentence is in every pack it lists and is learned once. Each direction is its own FSRS card from `srs.js`; neither card means new; both at stability ≥ 180 days means mastered. Bundled sentences have id `${pack}:${key}` and `bundled: pack`; your own have an `s…` id, no `bundled` and no `order`, and `from` (the book) when they came from reading. `it` can hold gendered forms, `{o|a}` (about you, `settings.trainMe`) and `{p:o|a}` (about your partner, `settings.trainPartner`), resolved by `genderize()`; `askGender()` asks once when a sentence that needs it comes up.
- `sentences.js` is pure and unit-tested (`tests/sentences-core.test.mjs`): `buildPlan()` (each step's due cards first, closest to forgotten first, then new ones within `settings.trainNew`; a sentence started in one direction is due in the other; Shadow takes today's new ones, then today's misses, then random others), `hint()` (Say it's three-step hint), `genderize()`, `level()`, `newOrder()` (the order new sentences come in: the focus pack's, then your own oldest first, then ready-made ones in pack order) and `sameText()` (same words, ignoring case and punctuation).
- `training.js` keeps every sentence in an in-memory `Map` (`loadSentences()`), puts a pack's sentences in the store the first time it's on (`syncPacks()`, tracked by pack `rev` in `langreader.packRevs`, never overwriting one that's there), and keeps today's counts in `langreader.trainDay` (`{date, listen, shadow, say, fresh, missed}`). The plan is the same size every day (`settings.trainListen/trainShadow/trainSay`). A finished step sets `days[].trained` for the streak; `days[].drills` counts cards.
- Packs come in three kinds, all reached through `packMeta(id)` (`kind`: `bundled`, `own`, `reading`). Your own are IndexedDB `packs` (`{id, name, emoji, colors: [dark, light], created}`, loaded with the sentences); From reading (id `reading`, `READING`) has no record and exists while it has sentences. Your own packs and From reading are always trained (`isTrained()`); ready-made ones once they're in `settings.trainPacks`. `deletePack()` deletes the pack's sentences except those also in another pack. `deleteSentence()` deletes yours but only *hides* a ready-made one, so `syncPacks()` can't bring it back; `editSentence()` sets `edited`. The focus pack (`focusPack()`, one at a time) only changes the order of new sentences (`trainingList()` → `newOrder()`).
- `mysentences.js` holds the sheets for adding: `trainThisSentence()` (the bubble's, the word card's and the review card's "Train this sentence" button, via `trainButtonHTML()`/`onTrainButton()`) puts the word's sentence in From reading, using the word's `exampleTr` when it's for that sentence, otherwise MyMemory's translation (then saved as `exampleTr`); an existing sentence (`findSentence()`) isn't added twice, and offline nothing is added. `newSentenceSheet()` has Italian and English fields: with only one filled, it offers MyMemory's suggestion for the other (`translate(text, {reverse: true})` for English → Italian) and saves nothing until Add. Also `packEditSheet()` (name, emoji, colour), `sentencePacksSheet()` (tick the packs; one at least) and `editSentenceSheet()`. A sheet that opens another sheet from its `onDone` is fine: `closeSheet()` only hides `#sheet` if nothing reopened it.
- `drill.js` is the full-screen session (`drillSheet()`): today's plan, `{extra}` for "Train 10 more", `{only: packId}` for one pack (rated, but today's counts are untouched; the pack's ⋯ → Train this pack), `{practice: ids}` for today's misses (no rating). A rating renders the next card before its save finishes, so Listen can play in the tap on iOS; the end screen and `onClose` wait for the save. After a hint, the best rating is Hard; the third hint shows the answer and counts as Again (a one-word sentence skips the first hint, which would be the whole answer). `speak(text, {slow: true})` is the 🐢 button. It's laid out like Focus mode: a step line (name, ⓘ for the intro, "n of N", Skip step), the step's toggle row (`toggleRowHTML()`/`flipToggle()` from `focus.js`), the card, and the actions and grades pinned at the bottom (`.fc-bottom`). A step's intro shows only the first time (the steps seen are in localStorage `langreader.trainIntros`; Words always has its intro). The toggles share Focus's settings: Listen and Shadow use `settings.focus.shadow` (Listen shows Translation and Speed), Say it uses `.recall` (Dual audio speaks the English prompt, and Speed). Grades: Listen has three (Didn't get it / Mostly / Got it = Again/Hard/Good), Say it Focus's four (`GRADES`), with no intervals. Shadow plays one sentence through `createPlayer()` (`config` forces Loop off), and Next appears only once its repeats are done. The end screen lists the missed sentences, each with ▶.
- `focus.js` is Focus mode (`docs/focus-mode-plan.md`): a pack played like a player, in two modes, Shadowing (Italian, then your turn, × Repeats) and Recall (the English shown or, with Dual audio, spoken by a device English voice via `speak(text, {lang: 'en'})`; a gap to say it; then the Italian). `createPlayer()` is the one playback loop (timers and `speak()` with `onend`, a length-based guess as fallback), used by the Focus screen (`focusSheet({pack, mode, ids})`, full screen, no intro, starts in the tap, holds a wake lock) and the pack page's ▶. Each mode's settings are `settings.focus.shadow`/`.recall` over `FOCUS_DEFAULTS` (replace the whole `settings.focus` object to save), read at the start of each sentence; `settings.focusMode` is the pack page's switch. Rating is optional and never advances: `rateCard(id, dir, g, {count: false})` (Shadowing → `listen`, Recall → `say`), and changing it calls `rerateCard(snap, g)`, which schedules again from the first rating's snapshot so it's one review. A sentence played through all its repeats bumps `days[].drills` once per session (`rateCard`'s `drill: false` avoids a second bump). Its settings open inside the same sheet (the shared sheet holds one thing), or from the pack page's ⚙︎ as `focusSettingsSheet()` with Start pinned.
- `trainview.js` renders the tab (Today card, with a ★ line for the focus pack; then the shelves Your Packs (From reading, your own, a New Pack tile), Ready-made, More to Add; ＋ in the header is New Sentence) and a pack's page in the same view (`page`; the back button returns to the tab, leaving the tab resets it). The page has a Shadowing | Recall switch, ⚙︎ and ▶ (plays the pack on the page through `createPlayer()`), then lists sentences in Italian only with a 🔊 each, the English a tap away per row (or Show English for all), the level as stars, a ⋯ per row for the sentence's sheet, and + Sentence; "Start Focus · N" is pinned above the tab bar (`position: fixed`, since the document scrolls, not the view). A pack's ⋯ has Train this pack, Focus on this pack, Add a sentence, Edit pack…/Delete pack (yours) or Add/Remove (ready-made). A sentence's sheet has Edit, Packs…, Pause and Delete.
- Packs: `samples/packs/index.js` lists them (`PACKS`, `DEFAULT_PACKS`); each pack is a module of `[key, Italian, English, context]` rows. Keys are permanent: append new rows with new keys and raise the pack's `rev`. To ship a pack: add its file and entry, add the file to `SHELL` in `sw.js`, and run `node tools/check-sentences.mjs` (unknown words, gender markup, sizes, and a cap on words outside the 2,000 commonest for `common` packs; its `EXTRA` holds hand-checked modern words missing from the lemma list). `tests/sentences.test.mjs` runs the same checks.

### Word lookup (`bubble.js` → `wordcard.js`)
- Tapping a word opens the small bubble. ⋯ opens the full card in the shared sheet. Phrases open the full card directly.
- The same bubble opens for a word on a review or Training card (`openCardBubble(span, {root, context})`): it sits in `#sheet-body` (positioned for it), has no ⋯ (the full card would replace the session's sheet), recolours the card's `.cw` spans of that word as its status changes, and closing it on a New word makes it LingQ 1, as in the reader. While it's open, a tap elsewhere in the sheet only closes it (✕ still closes the sheet), and moving to the next card closes it.
- Lookup order: the saved meaning, then Wiktionary (`dictionary.js`, used only when the translation language is English; it follows "… of *lemma*" links to the base form), then MyMemory (`services.js`). Both are cached in `tcache`. For an inflected form, `dictionaryHints()` first puts the base word's English sense into that form with `english.js` ("third-person singular past historic of *arrivare*" + "to arrive" → "he/she arrived"); it's pure and unit-tested in `tests/english.test.mjs`, and returns nothing when a sense isn't a "to …" verb (or a noun, for plurals). Google Translate links are plain URLs built by `googleTranslateURL`.

### Speech (`services.js` → `piper.js` → `tts-worker.js`)
- `speak()` uses a Piper neural voice that runs on the device. `settings.voice` `''` (the default) is Riccardo; `'piper:paola'` and `'piper:serena'` are the other two (`VOICES` in `piper.js`). `'system'` picks the best device voice, and any other value is a device voice's name. Until the Piper voice has loaded, or if it fails, the Web Speech voice speaks instead.
- With `settings.speakOnTap` (default on), `onTap()` in the reader says the tapped word or saved phrase. It has to call `speak()` synchronously in the tap, for iOS.
- `prepareVoice()` (called when the reader opens, and when the voice setting changes) starts the worker loading. The worker keeps one voice in memory and releases the previous one when you switch. `tts-worker.js` is a classic worker: `piper_phonemize` (espeak-ng in WebAssembly, one fresh instance per call) turns text into phoneme ids, one line per sentence, and ONNX Runtime runs the voice model. `piper.js` caches the last 60 clips and plays them through Web Audio. `unlockAudio()` has to run synchronously in the tap, for iOS.
- The models and runtime live in `voices/` and `vendor/` (see `vendor/README.md`): 28 + 64 + 64 MB of voices and 16 MB of runtime. `sw.js` serves those two folders cache-first from their own `langreader-assets-v1` cache, which survives `VERSION` bumps. So never change one of those files in place: give it a new name.
- `openApp()` sets the device voice unless you pass `voice: ''`, so only `tests/voice.test.mjs` loads the Piper voices.

### UI conventions (`ui.js`)
- `openSheet()` **replaces `#sheet-body` with a fresh element** every time, so a sheet's listeners never leak into the next one. Attach handlers to the returned body. `full: true` makes it full screen and closable only by its own buttons. `toast()` shows in the reader's `#r-toast` while the reader is open, otherwise in `#app-toast`.
- The accent is mint green: `--tint` for text and icons (deepened in light mode so it reads on white), `--tint-fill` (`#6fedbd`) for filled buttons, rings and bars, with `--on-tint` (dark green) as the text on it. The other colours are tuned to the mint's tone and live as tokens on `:root`: `--blue` (New), `--gem`/`--gem-ink` (gems, yellow), `--orange` (only "Still learning"/Hard in reviews and hard books), `--red`, `--purple`; `--green` is an alias of `--tint` (Known). Use the tokens, not raw colours; the reader's word colours (`--new`, `--new-ul`, `--lq`) follow the same hues per theme.
- The reader themes are CSS variables on `#reader[data-theme]`, plus a `.dark` class. While the reader is open, `documentElement[data-appearance]` is set so the shared sheets follow the reader's light/dark appearance.
- On iOS, `haptic()` (`haptics.js`) clicks a hidden `<input type=checkbox switch>`, because iOS Safari has no Vibration API. It only fires when called synchronously from a user gesture.
- `storage.js` asks for persistent storage, tracks backup reminders, and saves exports through the iOS share sheet (`navigator.share` with files) when available.

### Bundled content (`samples/`)
`sample.js` (*Un caffè a Bologna*) and `stories.js` hold the original stories. Each has a stable `id`. `addBundledStories()` in `app.js` adds each id once per device, never re-adds a deleted story, and skips titles already in the library. To ship a new story, append it to `STORIES` with a new id; existing installs pick it up on their next launch. Add its character names to `js/names.js` too.

`samples/series/` is *La casa gialla*, a graded series meant to take a reader from no Italian to the 2,000 most common lemmas over 20 books (`PLAN.md` has the story and the plan). Each book is its own module (`01.js` …, built with `book()` in `book.js`), loaded by `addBundledStories()` only if its id hasn't been added; book 1 gets the newest `added` date, so the series lines up first in the Library. To ship a book: add the file, raise `SERIES.books` and add its entry to `REVS` in `index.js`, add it to `SHELL` in `sw.js` and to the title list in `tests/library.test.mjs`, and run `node tools/check-series.mjs`. **Before writing a book, read `samples/series/PLAN.md` in full**: it holds the story, the house's rules, what's been written so far, open threads and the writing method. To change a released book's text, raise its number in `REVS` in `index.js`: libraries that have an older revision get the new text through `replaceBookText()` in `importer.js`, which keeps the book's id and progress. The checker reads the books with the app's tokenizer and lemma list against the word plan in `tools/series-words.mjs` (the target list, archaic words held back until book 16, per-book caps on unfamiliar words). `tests/series.test.mjs` fails on unknown words (usually typos), archaic words used too early, books over the cap, and book files missing from `SHELL`.
